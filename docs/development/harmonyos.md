# HarmonyOS 开发规范

## 1. 适用范围与工具

- 本规范适用于 HarmonyOS 应用的 ArkTS/ETS、ArkUI、资源、权限和依赖改动。
- 使用 `devecocli help` 查询实际可用命令和参数；不凭记忆拼接命令或假定工具版本。
- 新工程的最短验证流程如下；仅在工程师明确要求创建工程时执行。
-  npm install -g @deveco/deveco-cli@stable 为安装方式

```powershell
devecocli create --app-name MyApp
Set-Location MyApp
devecocli run
devecocli log --level E
```

- 先确认工程已有构建、运行与日志流程；不得为方便调试而替换现有工具链或配置。

## 2. ArkTS/ETS 编译约束

ArkTS 是静态类型语言。对象布局、模块边界与类型必须在编译期明确；禁止将标准 TypeScript 的动态写法直接迁入。

### 类型与声明

- 禁止 `any`、`unknown`、索引访问类型、索引签名、映射类型、条件类型、`infer`、交叉类型、结构化类型、`typeof` 类型标注、`this` 类型标注和字面量类型的 `as const`；使用显式类、接口、类型名称或继承替代。
- 不直接用对象字面量声明类型；对象字面量必须能推断到已声明的类或接口，且不得用于初始化 `any`、`Object`、`object`、含方法/只读字段/带参构造函数的类或接口。
- 禁止对象类型中的调用或构造签名、接口中的构造签名、构造函数类型和类字面量；需要行为与数据时定义具名类，需要回调时使用箭头函数。
- 接口不得包含仅返回类型不同的不可区分方法签名，也不得通过扩展引入相同方法签名；重命名方法或调整其参数以消除歧义。
- 禁止声明合并，包括枚举合并；每个类、接口、枚举定义保持完整且集中。
- 类字段必须在类体中声明并初始化；禁止在构造函数中声明字段及使用确定赋值断言 `!`。私有字段使用 `private`，不用 `#` 私有标识符。
- 枚举成员只能使用同类型的编译期表达式初始化；不得使用运行期表达式。
- 仅可使用 `Partial`、`Required`、`Readonly`、`Record` 等受支持的实用类型；使用 `Record<K, V>` 索引时处理 `V | undefined`。
- 泛型无法从实参推断时必须显式给出类型参数，尤其不得只依据返回类型推断；受限的返回类型推断场景应显式声明返回类型。

### 对象、函数与控制流

- 禁止动态字段声明、删除属性、以索引访问对象字段、重新分配对象方法、原型赋值、将类或命名空间当作对象、全局作用域和 `globalThis`；不得将类赋值给变量或以值方式传递。字段在类中显式声明，使用 `obj.field`，跨文件共享使用模块导入导出。
- 禁止解构赋值、解构变量与解构参数；改用中间变量并逐字段读取，参数直接传入函数后手动分配局部名称。
- 禁止 `for...in`、`in`、`is`；数组使用普通 `for` 循环，对象类型判断使用 `instanceof`，访问字段前使用 `as` 转为适当类型。
- 禁止函数表达式、嵌套函数、生成器函数、在函数上声明属性，以及独立函数或静态方法中的 `this`；回调使用箭头函数，多任务使用 `async/await`，`this` 仅用于实例方法。
- 禁止 `Function.apply`、`Function.call`、`Function.bind`、`new.target`、`Symbol()`（`Symbol.iterator` 除外）、`with`、`var`；使用传统 OOP、显式调用、`let` 或 `const` 替代。
- 逗号运算符仅允许出现在 `for` 循环；一元 `+`、`-`、`~` 仅作用于数值，字符串等值必须显式转换。
- 数组字面量的所有元素必须可推断，无法推断时声明元素类型或显式转换。

### 模块与导入

- 所有 `import` 必须位于文件其他语句之前；使用常规具名或默认 `import`/`export`。
- 禁止环境模块声明、导入断言、`require`、import 赋值、`export =`、UMD、模块名通配符；从原始模块导入实际需要的成员。
- 标准 TypeScript 代码不得通过导入 ArkTS 代码依赖 ArkTS；ArkTS 导入 TypeScript 可以使用时仍应确认工程兼容性。

### 其他限制

- 禁止 JSX；使用 ArkUI 声明式语法。
- 每个类只能有一个静态代码块；同类语句合并到该代码块。
- 命名空间中不得包含直接执行的语句；使用函数承载需要执行的逻辑。
- `catch` 变量不得标注类型；省略其类型标注。
- 展开运算符仅用于将数组或数组派生类展开到 rest 参数或数组字面量；其他场景手动解包。

## 3. HarmonyOS API、权限与依赖

- 优先采用官方 API、ArkUI 组件、动画能力和官方模板；不确定的语法、API、参数、返回值或兼容性必须查阅华为开发者官方文档后再实现。
- 调用 API 前确认所需 `import`、API Level、设备支持范围、线程/生命周期要求及错误处理方式。
- 需要权限时，在对应模块的 `module.json5` 中确认或添加最小权限，并与实际功能保持一致。
- 引入依赖前确认现有能力无法满足、依赖确实存在、许可证与目标版本兼容；在对应模块 `oh-package.json5` 中声明精确匹配的依赖，不混入无关升级。
- 使用 `@Component` 或 `@ComponentV2` 时保持与现有工程的兼容性和既有选型一致；切换版本或范式前先评估影响。

## 4. 资源与国际化

- UI 展示的文字、颜色、尺寸等常量优先定义为资源，并通过 `$r` 引用；不在界面中散落可本地化或可主题化的字面值。
- 新增字符串时同步补全工程已支持的每种语言资源；无法翻译时明确标注待补项，不得遗漏默认语言。
- 新增颜色、图片或主题资源时检查历史工程的深浅色策略；新工程默认同时支持浅色与深色主题。

## 5. ArkUI 动画

- 优先使用 HarmonyOS 原生动画 API、声明式 UI、`@State` 驱动状态变化，以及官方高级动画模板；常用能力包括 `animateTo`、`transform`、`renderGroup` 与 `opacity`。
- 通过改变状态变量触发动画，避免以命令式循环直接操纵界面。
- 包含复杂子组件的动画容器使用 `renderGroup(true)` 以减少渲染批次，并在目标设备验证实际效果。
- 动画过程中不得高频修改 `width`、`height`、`padding`、`margin` 等布局属性；优先使用 `transform`、`opacity` 等不会反复触发布局计算的属性。
