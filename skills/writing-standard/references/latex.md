# LaTeX 与 PDF 专项参考

仅当交付物需要 PDF、已有 LaTeX 源文件，或排版要求无法由普通 Markdown 满足时使用本参考。普通开发文档优先维护为 Markdown。

## 目录组织

按文档主题或交付物建立目录，将同一文档的 Markdown、LaTeX、PDF 与素材放在一起：

```text
docs/
  reports/
    2026-08-release/
      release-notes.md
      release-notes.tex
      release-notes.pdf
      assets/
```

主文件使用相同文件名。`assets/` 仅包含该文档引用的图片或图表；不要建立全局 `md/`、`tex/`、`pdf/` 目录，也不要为未使用的格式创建空文件或目录。以 `.tex` 为排版源时，明确其为唯一可编辑源，不与 Markdown 双向同步。

## 文档类型

按内容选择最简单的文档类：

| 场景 | 优先选择 |
| --- | --- |
| 短文、技术说明、论文式报告 | `article` |
| 演示文稿 | `beamer` |
| 章节较多的长报告、手册或书稿 | `report` |

项目已有文档类、模板或构建脚本时，优先沿用；不要仅为统一形式替换可正常工作的排版方案。

## 源文件与资源

* 不移动、重命名或覆盖现有 `.tex`、图片、参考文献和样式文件，除非任务明确要求。
* 图片使用相对于主 `.tex` 文件的路径；提交前确认路径大小写、扩展名和引用均正确。
* 中文文档以 XeLaTeX 编译；先确认目标环境可用的中文字体。字体不可用时，优先改用项目已提供的替代字体，并说明差异。
* 优先复用已有模板、字体设置和构建脚本；新增宏包或自定义命令前确认确有必要。
* `.aux`、`.log`、`.fdb_latexmk` 等辅助文件不作为文档交付物或版本控制内容；最终 PDF 需要正式交付时可与源文件一并保留。

## 编译

在主 `.tex` 文件所在目录，用 PowerShell 执行已有构建脚本；没有脚本时可使用：

```powershell
latexmk -xelatex -interaction=nonstopmode main.tex
```

将 `main.tex` 替换为实际入口文件。仅在需要完整错误定位时使用 `-interaction=nonstopmode`；不得把警告或编译错误当作成功。

## 问题诊断

编译失败时，从日志中定位第一个实质错误，并优先检查：

1. 文件路径、图片格式和资源是否存在。
2. 中文字体和所需宏包是否可用。
3. 引用、环境和花括号是否成对。
4. 交叉引用、目录或参考文献是否需要再次编译。

不要通过删除内容、静默忽略错误或反复盲目重试来掩盖问题。修改后重新编译，确认错误已消除。

## PDF 核验

生成 PDF 后至少检查：

* 页数、标题、目录、页眉页脚和章节层级是否符合预期。
* 中文字符、公式、代码和表格是否缺字、溢出或乱码。
* 图片清晰度、比例、位置及交叉引用、链接和页码是否正确。
* 最终 PDF 路径与源文件对应，未误提交临时版本。

清理 `.aux`、`.log`、`.fdb_latexmk` 等辅助文件可能影响本地调试；只有获得工程师明确授权后才能执行，并且不得删除源文件或最终 PDF。
